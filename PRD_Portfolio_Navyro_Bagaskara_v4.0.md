# 1. Product Overview

Website portofolio pribadi yang berfungsi sebagai pusat personal branding profesional. Website menampilkan profil, karya UI/UX, proses case study, pengalaman, kemampuan Front-End, resume, dan informasi kontak dalam pengalaman yang profesional, jelas, responsif, dan mudah dipahami.

Website harus menunjukkan bahwa pemilik portofolio tidak hanya mampu menghasilkan visual yang baik, tetapi juga mampu memahami masalah pengguna, menyusun solusi, membuat interface, dan memahami implementasi Front-End.

## 1.1 Product Vision

Membangun representasi digital profesional yang membuat recruiter dapat memahami:

1. siapa pemilik portofolio;
2. apa keahlian utamanya;
3. proyek apa yang pernah dikerjakan;
4. bagaimana proses berpikir dan problem solving-nya;
5. apa kontribusinya dalam setiap proyek;
6. pengalaman dan kemampuan teknisnya; dan
7. bagaimana cara menghubunginya.

## 1.2 Value Proposition

Portofolio memosisikan Navyro sebagai **UI/UX Designer + Front-End** dengan UI/UX sebagai kompetensi utama dan Front-End sebagai kompetensi pendukung.

Website harus memperlihatkan hubungan antara:

**Problem → Thinking → Design → Implementation**

bila konteks proyek memang mendukung.

## 1.3 Problem Statement

Recruiter memiliki waktu terbatas ketika mengevaluasi kandidat. Portfolio yang hanya berisi screenshot desain tidak cukup untuk menunjukkan kemampuan problem solving, kontribusi, dan proses kerja.

Website ini harus menyelesaikan masalah tersebut dengan:

- menampilkan positioning yang jelas;
- memprioritaskan karya terbaik;
- menyediakan case study yang terstruktur;
- menampilkan kontribusi pribadi;
- menyediakan informasi profesional secara ringkas;
- menyediakan CV dan contact yang mudah ditemukan.

# 5. Design Direction

## 5.1 Primary Visual Direction

**Professional Editorial + Minimalist**

Tujuan visual:

> Terlihat seperti portfolio seorang designer profesional yang dibuat dan dipikirkan secara sadar, bukan template generik atau website yang terasa dibuat oleh AI.

## 5.2 Desired Impression

Pengunjung sebaiknya mendapatkan kesan:

- professional;
- mature;
- confident;
- thoughtful;
- clean;
- intentional;
- design-oriented;
- technically capable.

Kesan utama:

> **“Orang ini memang designer.”**

Bukan:

> “Ini terlihat seperti template AI.”

## 5.3 Visual Principles

### 1. Typography First

Typography menjadi salah satu elemen visual utama.

Prioritaskan:

- hierarchy;
- ukuran;
- weight;
- line-height;
- spacing;
- alignment.

### 2. Strong Grid

Gunakan grid yang konsisten untuk:

- hero;
- project list;
- case study;
- about;
- footer.

### 3. Generous Whitespace

Whitespace digunakan untuk:

- meningkatkan readability;
- memberi fokus;
- memisahkan section;
- membuat portfolio terasa premium.

### 4. Limited Color

Gunakan:

- neutral background;
- primary text;
- secondary text;
- satu accent color bila diperlukan.

Hindari terlalu banyak warna.

### 5. Project Imagery as Hero

Karya harus menjadi visual utama, bukan dekorasi tambahan.

### 6. Subtle Interaction

Gunakan micro-interaction secara terukur.

Contoh:

- hover;
- image scale kecil;
- underline transition;
- opacity transition;
- subtle page transition.

### 7. Content Over Decoration

Dekorasi tidak boleh lebih dominan daripada:

- project;
- typography;
- content;
- navigation.

---

# 6. Anti-Generic / Anti-AI Visual Rules

Website **MUST NOT** menggunakan pendekatan visual yang membuatnya terlihat seperti template AI generik.

Hindari:

- gradient besar tanpa fungsi;
- glassmorphism sebagai gaya utama;
- blob decoration;
- floating 3D objects yang tidak relevan;
- terlalu banyak rounded cards;
- excessive drop shadows;
- neon color palette;
- excessive glow;
- dashboard-like layout;
- hero dengan terlalu banyak badge;
- terlalu banyak pill/chip;
- animasi berlebihan;
- copywriting generik;
- section yang terlalu banyak;
- elemen dekoratif hanya untuk memenuhi ruang.

### Copywriting yang dihindari

Hindari headline generik seperti:

> “I craft seamless digital experiences that inspire and delight.”

Lebih baik menggunakan bahasa yang:

- sederhana;
- spesifik;
- natural;
- sesuai pengalaman nyata.

# 23. Technical Requirements

## 23.1 Recommended Technology Stack

Untuk website portfolio ini, stack yang dipilih adalah **Next.js + TypeScript + Tailwind CSS**, dengan **GitHub** untuk version control dan **Vercel** untuk deployment.

Stack ini dipilih karena portfolio harus berfungsi sebagai website profesional sekaligus menjadi bukti kemampuan Front-End.

| Technology | Purpose | Decision |
|---|---|---|
| Next.js | Front-End framework dan routing | Selected |
| TypeScript | Type-safe development | Selected |
| Tailwind CSS | Styling dan responsive UI | Selected |
| GitHub | Source control dan repository | Selected |
| Vercel | Deployment dan hosting | Selected |
| Figma | UI/UX design dan prototyping | Selected |
| Markdown / local data | Content untuk case study | Recommended for MVP |
| Optional CMS | Content management | Not required for MVP |

## 23.2 Why This Stack

### Next.js

Next.js digunakan sebagai framework utama karena:

- cocok untuk website content-driven seperti portfolio;
- memiliki routing bawaan;
- mendukung rendering yang sesuai kebutuhan halaman;
- mendukung metadata dan SEO;
- memiliki optimasi image;
- dapat menghasilkan website yang cepat;
- cocok untuk project case study yang memiliki banyak halaman;
- dapat berkembang tanpa membutuhkan backend kompleks pada MVP.

### TypeScript

TypeScript digunakan untuk:

- meningkatkan type safety;
- mengurangi kesalahan implementasi;
- menjaga struktur data project tetap konsisten;
- membuat codebase lebih maintainable.

### Tailwind CSS

Tailwind CSS digunakan untuk:

- membangun design system secara konsisten;
- responsive styling;
- spacing dan typography yang terkontrol;
- mempercepat implementasi dari Figma;
- mengurangi CSS yang tidak digunakan.

Tailwind tidak boleh digunakan untuk menghasilkan utility-heavy markup yang sulit dipelihara. Reusable components tetap harus dibuat untuk pola UI yang berulang.

### GitHub

GitHub digunakan untuk:

- version control;
- project history;
- backup source code;
- dokumentasi repository;
- menunjukkan kemampuan development bila repository dipublikasikan.

### Vercel

Vercel digunakan sebagai deployment platform yang terintegrasi baik dengan Next.js.

Deployment harus:

- menggunakan HTTPS;
- memiliki production URL;
- dapat melakukan deployment dari repository;
- memiliki environment variable yang aman bila diperlukan.

# 35. Technology Decision

The MVP technology stack is fixed as follows:

**Next.js + TypeScript + Tailwind CSS + GitHub + Vercel**

Reasoning:

- Next.js provides a strong foundation for a professional content-driven portfolio.
- TypeScript improves maintainability and code quality.
- Tailwind CSS supports consistent implementation of the visual system.
- GitHub provides version control and a professional development workflow.
- Vercel provides a straightforward production deployment path for Next.js.

The stack should support the design rather than dictate it. Visual quality, usability, accessibility, performance, and content remain higher priorities than the use of any particular technology.
